# Grounded meeting intelligence

The application defaults to **Extractive mode**. Creation and local regeneration use transcript sentences, exact explicit commitments, and source links. No provider request is made in extractive mode. Vague deadlines remain blank. Regeneration leaves assignees blank rather than inferring responsibility from a speaker name. Manual, completed, and edited tasks and saved personal notes are preserved; only untouched open extracted tasks are replaced. Updated transcript revisions visibly mark prior generated content stale.

The optional OpenAI adapter uses the official SDK and [Responses structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs). It has a fixed `https://api.openai.com/v1` host, server-only credentials, `store=False`, no tools, no URL fetching, zero automatic retries, a 30-second deadline, and a 4,000-token output cap. Configure `LLM_PROVIDER=openai`, `OPENAI_API_KEY`, and an explicit `LLM_MODEL` supporting Responses structured outputs and a context window of at least 32,000 tokens. The bounded input plus output reserve must fit that selected model; unsupported configurations fall back visibly instead of blocking CRUD. The frontend offers provider mode only when configured and requires consent to send selected transcript text.

Summary input is an evenly distributed selection capped at 24,000 characters including per-turn overhead. This is a deliberately conservative input limit, not a claim of full coverage for a long meeting. Prompts separate instructions from serialized untrusted evidence and prohibit following embedded commands. Structured outputs are validated again on the server: source IDs must belong to supplied meeting evidence; task text must exactly quote an explicit commitment; duplicate generated items are rejected. This constrains model output but does not establish semantic correctness of every generated sentence; users can inspect sources.

A short transaction claims an idempotent request. The database writer is released during generation. A new write transaction verifies the same transcript revision and summary version before persisting any result. Concurrent transcript changes return a conflict without overwriting existing notes. Failed/cancelled operations can retry, concurrent duplicate keys return pending, and successful duplicate keys replay the stored response. Generation is limited to five requests per session per minute and two active operations across the single backend instance. Disconnected clients cancel pending generation; BFF cancellation propagates upstream.

Timeouts, invalid structured output, unsupported evidence IDs, invented commitments, and duplicate generated content produce a labelled extractive fallback. Provider errors do not expose raw responses or keys. Deterministic tests cover the SDK request boundary, success, fallback cases, disconnected requests, preserved work, idempotency, and a concurrent writer changing the transcript during generation. **A live provider call has not been verified because this environment has no configured API key.** To verify one, configure the backend, restart it, choose OpenAI in Regenerate notes, consent, and check the returned provider/model and source links on synthetic data.

## Meeting assistant

Meeting chat retrieves ranked FTS evidence only from the current workspace and meeting. It removes common question words, selects at most twelve source turns within 18,000 characters, and includes at most four recent messages of 600 characters each. OpenAI receives untrusted text inside a data object, no tools, no arbitrary endpoint, and no cross-meeting content. Citations must identify supplied turns. Unsupported questions return a fixed evidence-unavailable response. Prompt instructions reduce injection risk but do not prove semantic truth; source links let the reviewer inspect the evidence.

Extractive mode works without credentials and explicitly labels transcript excerpts. History persists for up to fifty exchanges per meeting; clearing it also removes replay payloads. A pending-state UI supports cancellation. Generation releases the SQLite writer lock and checks both meeting version and transcript revision before atomically saving the question, answer, and citations. Deterministic tests cover provider success, timeout, malformed output, invalid citations, and concurrent changes. No live provider call has been verified.

## Search and downloads

Global search uses parameterized FTS5 with quoted literal tokens, rank ordering, safe plain-text snippets, speaker/time context, and source links. Filters and all returned sources are workspace-scoped. Editing and deleting transcript text update the index transactionally.

TXT, escaped Markdown, and PDF downloads cover transcript, notes, tasks, or the complete notebook, with timestamp and speaker options. Large exports provide numbered parts containing at most 40,000 characters each; download every part for complete content. PDF embeds licensed DejaVu fonts and renders unsupported glyphs as explicit Unicode codes. TXT and Markdown preserve original Unicode. A narrow ReportLab 5.0.1 compatibility fix writes non-BMP PDF text mappings as UTF-16BE, preserving emoji extraction. Four rendered pages were visually reviewed for wrapping, page breaks, and footers; extracted text was checked for emoji, Greek, Cyrillic, and accented Latin. This does not imply support for every script or complex-script shaping.
